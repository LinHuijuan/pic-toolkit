# 🖼️ 图片工具箱 PicToolkit

> 一款**纯前端、全功能**的本地图片处理工具，12 个工具开箱即用，所有图片**全程在本机（浏览器）处理**，永不上传服务器。

用 AI 辅助开发的作品 —— 从 0 到 1 用 AI 完成封面设计、SVG 图标、页面布局与代码实现，做出一款「真能打」的实用工具。

## 🧰 功能一览

- **图片编辑** — 自由裁剪、旋转翻转，处理后可直接进入其他工具
- **九宫格切图** — 朋友圈发图神器，支持留白与透明背景
- **添加水印** — 文字 / 图片水印，平铺、单点放置，一套参数批量套用多张
- **AI 抠图** — 一键去背景，输出透明 PNG；边缘收缩 + 羽化吃掉头发丝周围的白边，换底色 / 背景图，加描边与投影做贴纸，笔刷还能擦掉残留（支持撤销）
- **图片压缩** — 本地压缩体积，按质量或目标体积，支持 JPG / WebP 输出与批量，结果一次打包 ZIP
- **长图拼接** — 多图竖排 / 横排拼长图
- **证件照换底色** — AI 抠图一键换底，发丝白边可收缩/羽化精修；内置 11 种规格（一寸二寸、四六级/教资、驾驶证、社保、美/加/申根签证）+ 自定义毫米尺寸，一版多张可导出 6 寸相纸打印 PDF，白/蓝/红三底色一键打包 ZIP
- **图片格式转换** — PNG / JPG / WebP 互转，HEIC 可直接读入，可选保留 EXIF 拍摄信息
- **网格拼图** — 多图拼网格，九宫格神器
- **超分辨率放大** — 本地 AI 放大，适合小图修复与二次排版
- **美颜修图** — 本地人脸检测，磨皮提亮只作用于人脸区域
- **局部改色** — 框选区域取色替换，改衣服、改Logo 颜色

导入支持 JPG / PNG / WebP / GIF / BMP / SVG / AVIF / TIFF / HEIC，页面任意位置拖拽或 Ctrl+V 粘贴即可喂图。

## 🛠️ 技术栈

- **Vue 3**（组合式 API + TypeScript）+ **Vite 6**
- **vite-plugin-pwa / Workbox** — 离线缓存与可安装，模型资源分层缓存
- **@imgly/background-removal** — AI 抠图（底层 **onnxruntime-web**，WebGPU 优先、失败自动回退 CPU）
- **@mediapipe/tasks-vision** — 本地人脸关键点，供美颜定位
- **自研 Canvas 管线** — 超分分块推理、alpha 膨胀描边、投影与擦除笔刷全部本地实现
- **hash 路由 + 视图分片**：每个工具按需加载，只下载用到的那份代码
- **零新依赖的导出层** — ZIP 打包、EXIF 段回写、HEIC 识别都是手写实现，不为此加一个包
- GitHub Pages 子路径部署（`/pic-toolkit/`）

## 🧠 几个值得说的实现细节

- **ZIP 只装不压**：图片本身已经是 JPG / PNG / WebP，deflate 再压一遍基本省不下字节，还要多背一个依赖。所以 `utils/zip.ts` 直接按 store 方式手写本地头 + 中央目录 + EOCD（约 100 行），文件名统一打 UTF-8 标记，中文文件名不会乱码。
- **EXIF 是显式 opt-in**：EXIF 可能含 GPS，而本项目的卖点是隐私。所以默认仍然把元数据剥干净，勾了「保留」才把 APP1 段回写进输出。回写时把 `Orientation` 改写为 1 而不是删标签——画布已经按原方向铺正了，删掉标签要重建 IFD，留着不改数字则会被二次旋转。色彩描述只认一个：Chrome 给 canvas 输出统一附一段 sRGB，此时再搬源 ICC 会让一张图带两份互相矛盾的 profile（画布在绘制时本就把像素转到了工作色彩空间，源 profile 描述的其实是转换前的值），所以输出自带 ICC 时不再搬。插入点取头部连续 APP0 段的末尾而非所有 APP 段末尾——Exif 规范要求 APP1 紧跟 APP0，落在编码器那段 ICC 之后 Windows 属性面板就读不到机型了。
- **HEIC 不能靠 MIME 判断**：Windows / Linux 的 Chrome 经常给不出 MIME，只能读文件头的 `ftyp` box 比对 brand 列表。解码走两级：先给原生 `createImageBitmap` 试（iOS Safari 直接成），失败才按需动态 import 一次 libheif 解码器，其他格式不会为它多付一点启动开销。
- **边缘处理排在描边之前**：收缩 / 羽化会改变轮廓，描边和投影必须沿着清理后的轮廓走，否则会描出一圈毛刺。三者都只做在 alpha 通道上（降采样后再做可分离方滤波），尺寸不变，所以预览的对齐和对比滑条都不受影响。也正因为只改 alpha，白边的颜色始终留在主体图层里：模糊会把掩码对称摊开约 feather 像素，刚腐蚀掉的白边会被重新糊出来，所以腐蚀量要额外加上羽化宽度，让柔化的外沿停在你收到的那条线上。
- **PDF 只封不排**：打印用的 PDF 与 zip.ts 同思路手写封装（约 70 行）：Catalog → Pages → Page 直接贴一张 JPEG（DCTDecode 直存不 deflate），页面尺寸按 300dpi 把像素换算成 pt，6 寸排版图换出来正好是 152×102mm 的相纸页面，打印店选「实际大小」直接出片，不为此多背一个依赖。
- **AI 任务不握在组件里**：视图一切换就被销毁，把 Promise 存在 `setup` 里等于丢进度。`utils/aiJob.ts` 是一个按工具分键的模块级登记表，状态挂在模块上、结果按 `runId` 回写，所以「开始推理 → 去别的工具 → 回来」看到的仍是同一次任务的进度与产物。

## 💡 设计理念

- **本地优先**：所有处理都在浏览器内完成，既是性能优势更是隐私承诺。
- **AI 落到实处**：不是"接入就完事"，而是让 AI 抠图与证件照真正可用且流畅（进度反馈、结果对比）。
- **体验至上**：空态可一键载入示例图、结果可拖动对比、前置进度提示，让工具「打开即懂、一玩就上头」。
